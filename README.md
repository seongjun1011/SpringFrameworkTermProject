# 학생정보시스템 (Student Portal) - Spring Boot

성준대학교 학생정보시스템/통합포털을 참고하여, 2학년 1학기 웹어플리케이션개발 텀프로젝트로 만든 학생정보시스템에
**Spring Data JPA**를 적용하여 모든 데이터를 DB에 저장하도록 확장한 프로젝트입니다.

## 주요 기술

- Java 17, Spring Boot 3.2.5 (Maven)
- Spring MVC (Controller - Service - Model 계층 구조)
- Thymeleaf (서버사이드 템플릿 렌더링)
- HttpSession 기반 직접 구현한 로그인/인증 (Spring Security 미사용)
- HandlerInterceptor를 이용한 접근 제어
  - 학생 화면: `LoginInterceptor` (로그인·초기 비밀번호 변경 여부 검사)
  - 교직원 화면(`/admin/**`): `AdminInterceptor` (교직원 로그인·역할 검사)
- Spring Data JPA + MySQL 8로 회원·강좌·수강신청·휴학/장학금신청·공지·채용·학사일정 데이터를 DB에 저장
- 학사팀 사전 등록 계정 + 로그인 (BCrypt 비밀번호 해시, spring-security-crypto) — 회원가입 없음
- OpenWeatherMap REST API 연동 (RestTemplate)으로 대시보드에 서울의 실시간 날씨 표시 (키 미설정·호출 실패 시 더미 데이터로 대체)

## 실행 방법

0. MySQL 8 서버 실행 (`localhost:3306`), `application.properties`의 계정으로 접속 가능해야 합니다.

1. IntelliJ에서 프로젝트 열기 (Maven 프로젝트로 자동 인식)
2. `StudentPortalApplication.java` 실행
3. 브라우저에서 `http://localhost:8080` 접속
4. 데모 계정으로 로그인

   | 학번 | 이름 | 비밀번호 | 비고 |
   |---|---|---|---|
   | `2301110329` | 박성준 | `1234` | 비밀번호 변경 완료 상태 |
   | `2301110301` | 김민준 | `040315` (생년월일) | 최초 로그인 → 비밀번호 변경 강제 |
   | `2401110302` | 이서연 | `050722` (생년월일) | 〃 |
   | `2401110303` | 최도윤 | `051109` (생년월일) | 〃 |

5. 교직원(관리자) 화면은 `http://localhost:8080/admin/login` (학생 로그인 화면의 "교직원 로그인" 링크)

   | 사번 | 이름 | 역할 | 비밀번호 |
   |---|---|---|---|
   | `A0001` | 정다은 | 학사관리자 | `staff1234` |
   | `S0001` | 이수진 | 담당직원 (결재자) | `staff1234` |
   | `S0002` | 최병철 | 학과장 (결재자) | `staff1234` |
   | `S0003` | 박현수 | 장학위원회 (결재자) | `staff1234` |
   | `S0004` | 김태호 | 학생처장 (결재자) | `staff1234` |

보안상 날씨 API 키는 저장소에 포함하지 않았습니다. 날씨 위젯에 실시간 데이터를 표시하려면
[OpenWeatherMap](https://openweathermap.org/api)에서 발급받은 키를 환경변수 `WEATHER_API_KEY`로 설정한 뒤 실행하세요.
(IntelliJ: Run → Edit Configurations → `StudentPortalApplication` → Environment variables에 `WEATHER_API_KEY=발급받은키` 입력)

키가 없거나 API 호출에 실패하면 더미 날씨 데이터가 표시됩니다.

## 구현된 기능

- 로그인 / 로그아웃 (JPA, DB 연동)
  - 실제 학사정보시스템처럼 **회원가입이 없고**, 학사팀이 학적 정보를 미리 등록 (`DataInitializer`)
  - 초기 비밀번호는 생년월일 6자리, **최초 로그인 시 비밀번호 변경 강제** (변경 전에는 다른 메뉴 접근 차단)
  - 비밀번호 규칙: 영문+숫자 8~20자, 학번·생년월일 포함 금지
  - 비밀번호 5회 오입력 시 계정 잠금
  - 비밀번호 초기화: 학번·이름·생년월일로 본인 확인 → 생년월일로 초기화 + 잠금 해제
  - 비밀번호변경 메뉴 (로그인 후 자발적 변경)
- 교직원(관리자) 로그인 / 로그아웃 / 관리자 홈 (`staffs` 테이블, 학생 세션과 분리)
  - 역할: 학사관리자(학적·수업·게시판 관리), 결재자(담당직원·학과장·장학위원회·학생처장 – 결재함)
  - 다른 역할의 메뉴에 접근하면 관리자 홈으로 돌려보내고 안내 메시지 표시
- 학적 관리 (학사관리자)
  - 학생 학적 등록: 학번(숫자 10자리)·이름·생년월일·학과·캠퍼스·학년 입력 → 초기 비밀번호(생년월일 6자리) 발급
  - 학생 목록 조회: 학번·이름 검색, 페이징(`Pageable`), 계정 상태(정상 / 초기 비밀번호 / 잠김) 표시
  - 계정 잠금 해제, 비밀번호 생년월일로 초기화
- 수업 관리 (학사관리자)
  - 강좌 개설·수정: 요일(월~금)·교시(1~6)·강의실·정원 검증, 같은 강의실·같은 시간 강좌 중복 금지
  - 신청한 학생이 있는 강좌는 요일·교시 변경 불가, 정원은 현재 신청 인원 이상으로만 수정 (행 잠금 후 수정)
  - 강좌별 수강신청 현황 (신청 학생 목록)
- 게시판 관리 (학사관리자)
  - 공지사항 작성: 작성 교직원을 `notices.staff_id`(→ `staffs.id`)로 연결, 학생 공지사항·대시보드에 바로 표시
  - 학사일정 등록: 하루 일정은 종료일 생략 가능, 학생 학사일정조회(월별)에 표시
- 결재함 (결재자: 담당직원·학과장·장학위원회·학생처장)
  - 앞 단계가 모두 승인되어 **내 역할의 차례**가 된 휴학·복학 / 장학금 신청만 표시
  - 승인·반려(반려 시 의견 필수), 처리자는 결재단계의 `processed_by`(→ `staffs.id`)로 기록
  - 반려되면 이후 단계는 진행되지 않고 신청 상태가 "반려"로, 마지막 단계까지 승인되면 "승인"으로 바뀜
  - 내가 처리한 결재 목록
- 통합포털 홈 (날씨, 주간 시간표, 학사일정, 채용정보, 공지사항 위젯)
- 수강신청 / 수강신청내역조회 (정원 초과·중복 신청·수업 시간 충돌 검증, 신청 시 confirm 확인창)
- 개인시간표조회 (교시×요일 격자, 과목별 색상 구분, 신청과목수·주간수업일수 요약)
- 개인신상정보수정 (연락처·주소·계좌번호 수정 / 학과·캠퍼스는 조회만 가능)
- 학사일정조회 (월별 조회, 이전/다음달 이동)
- 휴학/복학신청 (담당직원 → 학과장 → 학생처장 3단계 결재 흐름 표시)
- 장학금신청 (담당직원 → 장학위원회 → 학생처장 3단계 결재 흐름 표시)
- 공지사항조회
- 채용정보조회 (고용형태·급여·상세설명·지원자격 포함, 목록 클릭 시 상세 이동)

> 실제 학교 시스템의 메뉴 구조를 최대한 그대로 옮겼으며, 이번 과제에서 직접 구현한 기능은 위와 같습니다.
> 사이드바의 일부 메뉴(증명서발급신청, 등록금조회, 성적조회 등)는 화면 구조만 반영된 비활성 메뉴입니다.
> 휴학신청·장학금신청의 첨부파일은 `uploads/` 폴더에 저장되고, DB에는 원본/저장 파일명이 기록됩니다.

## 데이터 관리 방식 (JPA)

모든 데이터는 Spring Data JPA를 통해 MySQL 데이터베이스 `student-portal`에 저장되며, 서버를 재시작해도 유지됩니다.
(접속 계정은 `application.properties` 참고. DB가 없으면 `createDatabaseIfNotExist=true` 옵션으로 자동 생성됩니다.)
테이블은 엔티티 클래스를 기준으로 자동 생성되고(`ddl-auto=update`), 테이블이 비어 있을 때만
`DataInitializer`가 데모 데이터(학생·교직원 계정, 강좌, 공지, 채용정보, 학사일정, 결재 진행 중인 신청 내역)를 넣습니다.

| 테이블 | 엔티티 | 관계 |
|---|---|---|
| students | Student | 학번·생년월일·초기비밀번호 변경 여부·로그인 실패 횟수·잠금 여부 |
| staffs | Staff | 사번(유일)·이름·소속·역할(`@Enumerated(STRING)`) |
| courses | Course | |
| enrollments | Enrollment | students N:1, courses N:1 (학생-강좌 N:M 연결) |
| leave_applications (+ _steps, _files) | LeaveApplication | students N:1, 결재단계 processed_by → staffs |
| scholarship_applications (+ _steps, _files) | ScholarshipApplication | students N:1, 결재단계 processed_by → staffs |
| notices | Notice | 작성 교직원 staff_id → staffs |
| job_postings / academic_schedules | JobPosting / AcademicSchedule | |

DB는 하나이고, 계정별 데이터는 `student_id` 외래키로 구분됩니다. 수강신청·시간표·휴학/장학금 신청내역은
모두 로그인한 학생의 `id`로만 조회·저장하므로 학생마다 자기 데이터만 보입니다.

DB 내용은 IntelliJ Database 창(MySQL, `localhost:3306`, DB `student-portal`) 또는 MySQL Workbench에서 볼 수 있습니다.
